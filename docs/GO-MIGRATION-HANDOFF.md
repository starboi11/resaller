# Go backend migration handoff

Date: 2026-11-03. This is the latest local design working copy, based on design-v2.
The backend is still NestJS/TypeScript. No Go implementation has been written.

## Owner's product decision (confirmed 2026-11-03)
Only the owner sells on this site. The Go API therefore does NOT port: the resale
module, public seller onboarding and verification, store teams, and seller trust
levels. The Node modules still exist and still serve traffic until the switch;
removing the matching web/admin screens is a separate, explicit step.

## Sources to port
- `apps/api/src`: current controllers, services, guards, workers and tests.
- `apps/api/prisma/schema.prisma`: database model and relationships.
- `apps/api/prisma/migrations`: 22 SQL migration directories; preserve existing data
  and migration history. Do not recreate/drop production tables during the rewrite.
- `packages/types`, `packages/validation`, `packages/config`: shared contracts,
  validation and environment conventions.
- `apps/web` and `apps/admin`: actual API consumers; preserve their request/response
  fields, money encoding, status values, cookies and error behavior.
- `docs/resale/SPEC.md`, `docs/resale/HANDOFF.md`, `docs/design`: historical rules,
  implementation history and latest UI decisions, subject to the owner correction above.
- `e2e`, API `*.test.ts`, deployment scripts: existing regression evidence and scenarios.
- Compose, infrastructure and CI files: deployment foundations; update API service
  build/start and health checks when Go replaces Node, retain web/admin Node builds.

## Recommended delivery sequence
1. Inventory existing routes and authorization from controllers and guards, and
   record the actual JSON contract consumed by web/admin.
2. Implement health, errors, environment parsing, request IDs, logging redaction,
   sessions/cookies, CSRF origin checks and role/store authorization in Go.
3. Port read-only catalog and store endpoints, then stock/order transactions and
   idempotency. Preserve money precision, immutable order snapshots and deadlines.
4. Port media authorization, uploads, notifications, queues, chat/SSE and admin
   audit operations. Do not expose supplier/private data in buyer responses.
5. If resale remains in scope, preserve shared stock, manual payouts, owner-only
   payout requests and the hold rules documented in the specification.
6. Run equivalent API/DB concurrency tests and real authenticated browser flows
   against an isolated database. Compare Node and Go outputs before switching traffic.
7. Stage first; retain a tested rollback path. No live migration is authorized by
   this archive creation request.

## Archive contents and limitations
This private handoff contains repository source, assets, docs, tests, configuration,
local `.env`, and local preview artifacts. It excludes regenerable dependency/build
caches: node_modules, .next, .turbo, dist, coverage, .git and tsbuildinfo files.
Use the lockfile to reinstall dependencies; these caches are not business data.
The `.env` is the LOCAL development configuration, not a verified production secret
bundle. No secrets are printed in this document. Do not upload this private archive
to GitHub or share it publicly.
No PostgreSQL database dump, remote R2 objects or production-only secrets have been
retrieved. No separate local upload/data directories were present in this working copy.
Thus this is a full local source/config handoff, NOT a complete production backup.
`SOURCE_MANIFEST.json` at root came from the input release and predates local edits;
the sibling SHA256 hash verifies the new archive, not that older source manifest.

### Accounts and admin access — 2026-11-04 (Claude, on the Warm Studio build)
Base: `resaller-owner-final-warm-studio-2026-11-04.zip` (Warm Studio kept as is;
only the files below changed).

Owner requests: registration = name, phone, username, password; sign-in =
username + password; simple account page; customer password "6 characters is
enough"; a separate admin account with a 16-character random password and NO
2FA; an admin page address that cannot be found by fuzzing.

Changes
- DB migration `20261104090000_user_profile`: `User.fullName`, `phoneEncrypted`
  (AES-GCM), `phoneHash` (HMAC, unique: one account per phone). Existing rows NULL.
- Register DTO: fullName 2–80 (no digits/markup), phone normalised to
  `+998XXXXXXXXX` from any common spelling, username, password min 6 (digits
  allowed). Reset and new change-password use the same min 6.
- New endpoints: `GET /auth/profile` (own name/phone, decrypted),
  `POST /auth/password/change` (current + new; signs out other devices).
- Admin policy: `ADMIN_TWO_FACTOR_REQUIRED` (default true; owner sets false).
  When false, privileged users sign in with the password only; in exchange:
  5 tries / 15 min per admin account, `ADMIN_LOGIN` event per sign-in, 12-hour
  admin sessions, and admin passwords must be 16+ mixed characters on every
  change path. `apps/api/src/scripts/admin-account.ts` (`create`/`reset`) is the
  only way to make an admin; it prints a generated password once.
- Secret admin path: `ADMIN_BASE_PATH` (from `scripts/generate-admin-path.mjs`,
  192 random bits) as Next `basePath`. FOUND BY FUZZING: Next's own 404 page
  links assets under the secret path, so every 404 revealed it (291/292
  responses). Fixed with `apps/admin/server.mjs` (plain 404 for everything
  outside the path, before Next) and a Caddy rule that forwards only the path.
  Also found: `next start` re-reads basePath, so the image now refuses to build
  OR start without it (`ADMIN_REQUIRE_BASE_PATH=true` in the image/compose).
- Go API: same register/profile/change-password/admin rules; `DecodeBody` now
  reports unknown properties together with field errors, as Nest does (a real
  difference parity exposed once the new required fields existed).
- Web: register/login form, simplified account page (profile, password change,
  orders, sign out; devices folded; channel form removed), checkout prefill.
- Pre-existing bug fixed: `infrastructure/Caddyfile` had one-line `handle {…}`
  blocks that Caddy 2.10 rejects ("Unexpected next token after '{'"), i.e.
  production Caddy could not start. Expanded; `caddy validate`: Valid.
