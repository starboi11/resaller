## Work performed

The HTTP gap also explains a concrete login failure mode: a CORS preflight from `http://resaller.uz` to the HTTPS API returned no `Access-Control-Allow-Origin`, whereas the same preflight from `https://resaller.uz` returned the allowed origin. Do **not** allow insecure HTTP in CORS; redirect HTTP visitors to HTTPS before the page loads.

- Added authenticated owner-only preview for listing draft images and removed the broken public preview path from the seller UI.
- Added browser checks for a persisted session cookie, `/auth/me` after reload, draft image rendering after reload and anonymous denial of its private URL.
- Added `pnpm test:live-smoke` (`LIVE_ORIGIN=https://resaller.uz`) to verify both hosts' HTTP redirect/HSTS, public and protected APIs, and readiness without changing production data.
- `pnpm check` passed after the code changes. PostgreSQL concurrency/unit tests passed (55/55 before adding three media authorization tests; the media test run passed 57 tests with one existing optional integration skip). The final full browser suite passed **134 tests, with one pre-existing Windows/iPhone long-journey skip**, across Chromium, Firefox, WebKit, Android and iPhone emulations. A new non-owner draft-media assertion was added afterward and rerun separately in Chromium.
- Ran a controlled production registration/login/logout API check and one deployed Chromium browser registration check. These left disposable test accounts in production; no orders or seller data were created.

## Live blockers and next release gate

1. In the Cloudflare account that owns the DNS zone, enable **Always Use HTTPS** for `resaller.uz`; verify both root and admin hosts return a redirect on HTTP. Then enable and verify HSTS after confirming HTTPS works on all required subdomains. The currently connected Cloudflare API account does not list the zone.
2. Freeze and deploy a tested commit containing the local account, cart, seller and media fixes. GitHub CI does not deploy the server automatically; coordinate the server checkout/container rebuild explicitly. Compare the deployed release to that commit.
3. Run the controlled seller upload → R2 read → reload → admin approval → buyer image access and private-document denial tests on staging with real R2 credentials. Health `storage: up` only checks bucket heads, not object writes/reads.
4. Run the deployed E2E against staging and record backup/restore, rollback, alert, credential-rotation and legal/beta evidence before production sign-off.

The earlier statement that the site was effectively complete was not supported by this evidence. This audit is intentionally not a 100% approval.
