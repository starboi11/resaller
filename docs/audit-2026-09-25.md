# Resaller verification — 2026-09-25

This report separates local test results from read-only production checks. It is not a production sign-off.

## Local results

- `pnpm check`: passed (schema validation, secret scan, lint, typecheck, unit tests, and production builds).
- PostgreSQL integration/concurrency run: passed, 24 test files and 55 tests.
- `pnpm test:e2e`: 134 passed, 1 skipped across desktop Chromium, Firefox, WebKit, mobile Android and iPhone emulations. The skipped case is the long multi-context commerce journey on Windows iPhone/WebKit; shorter iPhone authentication, responsive, accessibility and visual checks ran.
- The seller → admin → buyer → fulfillment → verified-review journey passed on desktop Chromium, Firefox, WebKit and mobile Android. This runs against an isolated local E2E database, not production.
- `pnpm audit --audit-level high`: no known vulnerabilities reported.
- ClamAV EICAR stream check: signature detected (`FOUND`) using a temporary local scanner container, removed after the test.
- `pnpm format:check`: failed; 174 files are not Prettier-formatted, including generated Prisma files. This is a code-style gap, not a failed runtime test.

## Read-only production checks

- Public home, marketplace, categories, login, cart and seller-manage pages returned HTTP 200 over HTTPS. The API readiness endpoint returned 200 and reported database, Redis, queue and storage as up; this is the application's health report, not an independent infrastructure audit.
- Public categories and marketplace APIs returned 200. Unauthenticated requests for account, cart, orders, seller stores and admin queue returned 401.
- **High-priority security finding:** both `http://resaller.uz/` and `http://admin.resaller.uz/` returned HTTP 200 instead of redirecting to HTTPS. HTTPS web/admin responses did not contain HSTS. Force HTTPS at the edge and verify both hosts and all paths before accepting production traffic.
- Local working-tree changes, including the seller draft-form fix, are uncommitted. The production deployment must not be treated as the same release that passed local tests.

## Not verified in this run

- No production order, account, moderation or upload was created. Production commerce and admin journeys require a controlled staging or beta environment.
- No independent staging migration, deployed E2E, TLS scan, penetration test, external backup/restore, rollback, alert delivery, firewall/private-network, R2 authorization boundary, notification-provider, or sustained SSE/load test was completed.
- Legal approval, support/moderation operational sign-off, credential rotation, closed beta and final visual acceptance require separate evidence. See `docs/launch-checklist.md` (which currently contains stale pre-deployment wording and must be reconciled with the live site).

## Release decision

Local functionality has substantial automated coverage, but this run does **not** establish 100% readiness. The HTTP-to-HTTPS finding is a release blocker. After fixing it, deploy an immutable tested commit to staging, run deployed journeys and operational/security gates, and record owner approval before claiming production readiness.
