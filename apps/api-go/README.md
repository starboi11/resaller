# Resaller API — Go

Go port of `apps/api` (NestJS). It serves the same routes under `/api/v1`, on the
same PostgreSQL schema and Redis keys, with the same cookies, encodings and error
bodies, so Node and Go can run side by side and traffic can move route by route.

Product scope (owner decision, 2026-11-03): **only the owner sells**. Reseller,
public seller onboarding/verification, store teams and seller trust levels are not
ported. See `docs/GO-MIGRATION-HANDOFF.md` for the module plan and status.

## Run locally

```bash
cd apps/api-go
go run ./cmd/api            # reads ../../.env when DATABASE_URL is not set
API_PORT=4100 go run ./cmd/api   # next to the Node API on :4000
```

Requires Go 1.22+. Database migrations stay in `apps/api/prisma/migrations`; the Go
API never changes the schema.

## Tests

```bash
go test ./...                                   # unit tests, no services needed
./parity/run-parity.sh /path/to/test.env        # Node vs Go on one isolated DB
```

`parity/run-parity.sh` starts the built Node API (`apps/api/dist`) on :4000 and the
Go binary (`GO_BIN`, default `/tmp/resaller-go`) on :4100, creates two admin
accounts, and runs `parity/parity.mjs`: identical requests to both backends,
volatile values masked, status codes, JSON bodies and security headers compared,
plus cross-backend session and TOTP checks. Use a throwaway database.

`internal/secure/testdata/node-fixtures.json` is generated by
`make-node-fixtures.mjs` with Node's crypto; the Go tests prove that passwords,
session tokens, AES-GCM payloads (current, legacy and rotated keys) and TOTP codes
are byte-compatible in both directions.

## Offline/sandboxed builds

`go.mod` replaces `golang.org/x/*` with their GitHub mirrors (same code) and stubs
`gopkg.in/yaml.v3`, a test-only dependency of a dependency. Normal machines can use
the default Go proxy; `GOPROXY=direct GOSUMDB=off` works where only GitHub is reachable.
